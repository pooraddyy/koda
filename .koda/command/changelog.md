Review the requested diff, existing changesets, and any relevant tests. Draft a
release-ready summary that explains observable user impact, migration steps, and
known limitations without exposing implementation noise or unverified claims.

Use present-tense, concrete language. Group related behavior under short headings
only when it improves scanability. Do not create a release, update a version, or
modify files unless the user explicitly asks after reviewing the draft.
